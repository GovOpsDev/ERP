# Procurement design — PARTIAL

`erp.procurement.request` and its lines use Organization Contract v1, including independent company and active assigned-OU record rules. A sequence numbers requests. The actual states are draft, to_approve, approved, rejected and done. Editing is limited to draft. Submission simulates the combined request budget in a savepoint and rolls the temporary moves back. Company-specific tiers snapshot ordered reviewer identities; each pending reviewer must have Procurement capability and an active OU assignment. Each tier checks budget; the final approval reconciles a persistent PR commitment in the same transaction. Rejection reverses commitment. Tier thresholds use strictly greater-than comparison except the baseline zero threshold.

Native purchase orders link each PO line to at most one request line; one PR line may link multiple PO lines/orders. PO state writes reconcile from currently confirmed lines. A confirmed order replaces the full PR-line commitment, even for a partial order; cancelling the final confirmed PO restores PR commitment. PO lines may use different period, fund, analytic account, account/KPI and dimension keys; the Budget adapter resolves and locks both PR and PO controls. PO lines must use one 100% native analytic distribution; foreign currencies, taxed PO lines and multiple distribution combinations are rejected. Product expense accounts are checked from native Odoo and fiscal position. These restrictions are intentionally fail-closed while the Budget service cannot safely reconcile the more general cases.

The implementation is a narrow, custom PR-specific tier adaptation inspired by the inspected OCA 15.0 and NSTDA hooks, not full OCA tier-validation parity. Formula tiers, group/role approvers, delegation, comments, notifications, corrections, verified substate, rejection/cancellation policy, requisition and reports remain missing. Default tier definitions and reviewers are not seeded. Budget ledger source ownership relies on this adapter checking source access and state, and `_reconcile_purchase_multi` remains a private experimental API. Invoice actuals are supplied by the optional `erp_finance` adapter for its tested supported subset; Procurement alone does not implement them.

Global record rules restrict PR-linked purchase orders/lines by the PR organization; purchase orders with no PR link remain governed by native Purchase security. A stored derived OU and serialized scope edits prevent a linked order containing requests from different OUs. Contacts remain on native security. This is an incomplete workflow, not a production-readiness claim.

Without Finance, the guard rejects posting an invoice or refund linked to a PR-controlled PO. When `erp_finance` is installed, its controlled native posting path validates and reconciles supported bills atomically; direct state writes and attempts to add linked lines to a posted move remain guarded. Unrelated vendor bills retain native behavior. Finance limitations are documented in the Finance lifecycle.
