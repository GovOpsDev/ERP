# Technical module rename

`erp_base_organization` became `erp_organization`; `erp_base` became `erp_core`. Clean databases discover and install the new names from their canonical addon paths. Python imports, manifest dependencies, XML security references and tests were renamed. The model name `erp.organization.unit` remains unchanged. XML IDs are namespaced by technical addon name, so group, access, view, action and menu external IDs change.

Existing databases with either old module installed are **not upgraded by renaming the directory**. The module registry, dependencies and `ir.model.data` namespaces still point to old names; blindly installing both may duplicate metadata or conflict with existing tables and leave security records inconsistent. Old test databases remain untouched. For a future migration, first back up and restore-test the specific database and filestore, audit installed versions and references, then design and rehearse an explicit supported module-rename/migration script covering registry entries, XML IDs, dependencies, security, model metadata and rollback. Verify against a restored isolated copy before production. No compatibility shim or production migration is included here.
