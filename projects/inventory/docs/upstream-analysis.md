# Upstream analysis — source observations

`purchase_work_acceptance` at OCA/purchase-workflow 7eed5d2dd34d14edd74c6c80c235d0c75619f1d8 (15.0, AGPL-3) depends on `purchase_stock`. It creates a numbered `work.acceptance` with draft/accept/cancel, vendor, PO, responsible user, due/received/accepted dates and lines tied to purchase lines. Its documented path is confirmed PO → accepted WA → optional linked incoming receipt → optional linked bill. It supports service lines without stock movement. It calculates accepted PO quantity from accepted lines; drafts are excluded from that total. Upstream has no separate rejection quantity or committee engine in this module. It does not create budget moves. UI configuration groups can enable or enforce selection; its server-side comparisons apply when a WA is linked, not a universal server-side gate.

A linked receipt compares aggregate product quantities with accepted goods; a linked bill compares aggregate product quantities with all accepted lines. It does not establish an automatic return or asset-reversal process. Native stock remains authoritative for receipts, backorders and returns. These source findings are now implemented and runtime-tested; see source-mapping.md for the current closure decision.

NSTDA/OCA l10n-thailand 5ebe30a8be970d2d0b9504e18606a5d0b90df1e6 `l10n_th_gov_account_asset_management` depends on `purchase_work_acceptance`, `account_asset_low_value` and Thai asset management. Its only WA-specific model override uses the linked bill WA's acceptance date for the Asset start date. Exact OCA account-financial-tools 3bd0064b002af78f0d56745c6480d1f3c4fe0d76 `account_asset_management` creates an asset on posting an accounting move for a non-tax line with `asset_profile_id`, skipping lines already linked to an asset; the profile can be defaulted from the account. Thus acceptance alone does not establish asset eligibility or create an asset. The target Asset integration implements this behavior and its current lifecycle is described in asset-handoff-contract.md.

OCA/account-financial-tools branch 20.0 at `fca00f802a8802560a04e0941d779236a01f5e0c` was separately inspected; it contains no asset-management addon. This does not make the available 15.0 source unavailable, and is not evidence of a completed Asset migration.

Later selected committee/evaluation/tier, fines, installment and stock-request modules are covered by the exact-source closure matrix in source-mapping.md; the absence of committees in the base WA addon is not a reason to drop the government extension.
