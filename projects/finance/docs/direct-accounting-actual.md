# Direct accounting actuals

Required source: `account-budgeting/budget_control/models/{account_move,account_move_line,account_journal}.py` creates account-side actuals for native posted accounting documents, independently of a purchase/contract source. The document/journal `not_affect_budget` flag supplies explicit exemptions. Target REDESIGNED as optional explicit company/OU/period/fund/analytic/activity dimensions on native accounting lines, native posting/reset and the same immutable Budget ledger. Source uses one primary analytic plus tags; the equivalent target combination remains100percent. Arbitrary percentage splitting is not established by that source contract and is not silently inferred.

The Budget service's actual-only reconciliation cannot create commitments. A posted document with mixed direct/PO/Contract sources prelocks all activity, control and period scopes; its private transaction context checks the combined final control and parent totals. Intermediate replacement of one source does not incorrectly reject a valid final document. The context is a Python ContextVar with an exact user/database/control scope, not a client context bypass. Existing date, company, OU, key, fiscal seal and provenance checks remain. Posting or reset failure rolls back native accounting and all ledger changes together.

Native `_get_rounded_base_and_tax_lines(round_from_tax_lines=True)` supplies included company-currency tax components, preserving manual tax amounts and native rounding. Net actual remains the native signed balance. Invoice/refund/date/rate/tax edits after posting are blocked, and each new actual/reversal captures its amount policy. Budget history prevents deleting or moving an accounting source line even after its optional dimensions are cleared in draft. Native journal/bill exemptions are captured when documents are created; overriding the journal default requires Budget/Accounting management authority. They cannot exempt a PO/Contract source from commitment reconciliation.

Direct document access inspects every line using Odoo20 internal `any!` domains, including lines hidden by their own OU rule. Ordinary `not any` would hide the unauthorized line and accidentally expose the parent; the runtime revocation regression detected this and now covers header, expense and offset lines. Native company rules remain in force. Budget all-OU authority does not grant access to other OU accounting documents.
