# Asset architecture — PARTIAL

`erp.asset.asset` is an immutable acquisition/provenance record, not a second depreciation state machine. One optional unique `account.asset` link owns the OCA depreciation lifecycle. An Asset manager explicitly creates a draft engine asset with a matching OCA profile; existing acquisitions can be linked without automatically backfilling historical bills. Company, OU, bill/line, PO/line, acceptance/date, quantity and company-currency value remain on the acquisition. Engine source fields and profile accounting settings are protected after linking.

OCA independently creates an asset from a posted bill line carrying its `asset_profile_id`. ERP rejects posting where that path and an active ERP acquisition profile overlap for the same company/account. Clear the native account's OCA default profile for the ERP acquisition path and configure the OCA profile on the ERP profile instead. Account/profile locks serialize configuration against posting; database uniqueness and line locks guard duplicate acquisition, links and depreciation posting. Contention can cause a transaction to require retry.

Aggregate mode makes one acquisition per eligible bill line. Item mode requires an integral quantity and makes numbered individual acquisitions, allocating rounded company-currency value with the remainder on the last item. Each may be explicitly linked to one engine asset. This redesign avoids splitting accounting invoice lines.

A one-to-one link does not represent OCA AUC transfers that split or merge value across assets. A separate immutable transfer event now links source and destination accounting assets for a restricted same-company and same-OU AUC flow, without assigning individual source values to each destination. Existing acquisitions stay unchanged and each descendant has an explicit OU scope. See `transfer-architecture.md` for restrictions and evidence. OU/location/custodian history, refund/reversal, low-value and Thai lifecycle parity remain incomplete.
