# ภาษาไทยสำหรับ GovOpsDev ERP บน Odoo 20

คำแปลติดตั้งในฐาน local `erp_restored_final_verified` สำหรับผู้ใช้ที่เลือกภาษา
Thai / ภาษาไทย (`th_TH`) โดยใช้ไฟล์มาตรฐาน Odoo `i18n/th.po` ของ 11 โมดูล
`erp_*` ครอบคลุม Organization, HR, User Role, Budget, Procurement, Finance,
Contract, Inventory, Asset และ Shared Core ทั้งเมนู ปุ่ม ฟิลด์ สถานะ
ข้อความช่วยเหลือ ข้อความตรวจสอบสิทธิ์/เงื่อนไข และคำอธิบายโมดูลตามรายการ
ที่ Odoo ส่งออกจากฐานทดสอบ

โมดูลทรัพย์สิน OCA สองตัวมีคำแปลเพิ่มเติมใน `i18n_extra/th.po` โดยไม่แก้
Python หรือ XML ต้นฉบับ OCA ส่วน `erp_core/i18n_extra/th.po` เติมคำแปลเฉพาะ
จุดสำหรับเมนู ฟิลด์ และข้อความบนเว็บของ Odoo Community ที่พบในหน้าทดสอบ
ภาษาอังกฤษยังคงใช้งานได้เมื่อผู้ใช้เลือก English

## ขอบเขตและผลตรวจ

- Odoo export จาก 11 โมดูลมี 2,248 ข้อความต้นฉบับ และจากโมดูล OCA สินทรัพย์
  สองตัวมี 302 ข้อความ การตรวจเทียบครอบคลุมทั้งสองชุด ยกเว้นรหัสเทคนิคที่
  ไม่ใช่ข้อความแสดงผลและ markup ที่มีเพียงเครื่องหมาย `%`; ข้อความที่เป็น
  ภาษาไทยอยู่แล้วคงไว้
- ไฟล์ภาษา 14 ไฟล์มี 2,859 รายการ ไม่มี placeholder ผิดคู่ตามการตรวจอัตโนมัติ
  และในการติดตั้งภาษาเดิมได้ตรวจข้อมูลที่ Odoo โหลดจริง 3,097 รายการโดยไม่พบความคลาดเคลื่อน
- ทดสอบโหลดไฟล์ผ่านตัวโหลดโมดูล Odoo ในฐานสำเนา รวมทั้งข้อความผิดเงื่อนไข
  จริงทั้งภาษาไทยและอังกฤษ ตรวจ browser หน้าข้อตกลง งบประมาณ ใบขอซื้อ
  ใบสั่งซื้อ ตรวจรับ การเงิน และทรัพย์สิน และตรวจ API ฟอร์ม 14 ประเภท
- ตรวจบัญชี `trial_demo` หลังเปลี่ยนภาษา: มองเห็นสัญญาและไม่เห็น Apps/Settings;
  health checks 10 ข้อผ่าน
- Odoo Community พื้นฐานใช้ชุดภาษาไทยเดิมร่วมกับส่วนที่เติมเฉพาะจุด ไม่ได้
  อ้างว่าตรวจทุกหน้าของทุกโมดูลมาตรฐาน ข้อความธุรกิจ ชื่อข้อมูล กิจกรรม
  และประวัติที่ผู้ใช้หรือระบบบันทึกไว้ก่อนหน้าไม่ได้ถูกเปลี่ยนภาษา

แคชภาษาใน browser อาจยังแสดงข้อความเก่า ให้บันทึกงานที่ค้างก่อน แล้วเปิด
[ระบบ local](http://localhost:18069) ในแท็บใหม่หรือรีเฟรชอีกครั้งหลังโหลดเสร็จ
หากยังไม่เปลี่ยน ให้ออกจากระบบแล้วเข้าสู่ระบบใหม่และตรวจว่าภาษาผู้ใช้เป็น
Thai / ภาษาไทย

## การตรวจและกู้คืน

ไฟล์แปลถูกเก็บในแต่ละ repository ตามโมดูล และใช้ตัวโหลดภาษาปกติของ Odoo
ตัวตรวจใน `ops/readiness/check_thai_catalogs.py` รันภายใน image ที่มี `polib`:

```bash
docker exec -u odoo erp-readiness20-app-1 python3 /mnt/erp/ops/readiness/check_thai_catalogs.py --custom-pot /tmp/nstda-egov-ui.pot --oca-pot /tmp/nstda-assets-oca.pot
```

คำอธิบายแพ็กเกจ OCA เดิมอาจเป็นข้อมูล `noupdate` หากต้องอัปเดตคำแปล
บนฐานที่ติดตั้งอยู่แล้ว ให้สำรองฐานก่อน แล้วรัน `odoo shell` กับฐานที่ระบุ
โดยส่ง `ops/readiness/refresh_thai_package_descriptions.py` ทาง stdin สคริปต์
บังคับเขียนทับเฉพาะคำอธิบายภาษาไทยของโมดูล OCA สินทรัพย์สองรายการ

ไฟล์ POT เป็นผลส่งออกจากฐานทดสอบ ณ เวลาตรวจ ไม่ใช่ source catalog ถาวร;
ส่งออกใหม่ด้วย `odoo i18n export -l pot` เมื่อต้องตรวจข้อความหลังเปลี่ยนโค้ด
หลักฐานอยู่ที่ `test-evidence/thai-localization-20261031/` นอก repository

ก่อนนำภาษาเข้า ได้หยุด writer และสร้าง DB + filestore สำรองที่
`test-evidence/production-readiness-20261031/pre-thai-localization-backup/`;
ทดลอง restore ไปยัง `erp_restored_th_rollback_check` แล้วพบ `trial_demo`,
ข้อจำกัดเมนูทั้งสอง และไฟล์แนบ 71 รายการครบตาม checksum ภายใน Odoo
สำเนานี้เป็นข้อมูลก่อนแปล การกู้คืนในอนาคตต้องคำนึงถึงงานที่ทำหลังสำรอง
และใช้ขั้นตอนใน `production-readiness-runbook.md`
